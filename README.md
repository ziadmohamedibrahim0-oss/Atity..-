# AgriSense AI 🌱

نموذج أولي لنظام ذكي لدعم القرار الزراعي لمحصول الطماطم: **جدولة الري** (FAO-56) + **تقدير ET₀ بالتعلم الآلي** + **تشخيص أمراض الأوراق** + **لوحة قرار** (Streamlit + SQLite).
قسم هندسة النظم الحيوية – كلية الزراعة – جامعة بنها.

## التشغيل السريع

```bash
python -m venv .venv
source .venv/bin/activate          # ويندوز: .venv\Scripts\activate
pip install -r requirements.txt
streamlit run app.py
python -m unittest discover -s tests -v    # الاختبارات
python tests/smoke_app.py                  # تجربة منطق الواجهة بلا Streamlit ولا إنترنت
```

الواجهة بالعربية والإنجليزية (من الشريط الجانبي). ملف `requirements.txt` خفيف عمدًا (مناسب للنشر على Streamlit Cloud)؛ أما PyTorch ففي `requirements-disease.txt` ولا يلزم إلا لتدريب أو تشغيل مصنّف الأمراض (`pip install -r requirements-disease.txt`). بدونه يعمل كل شيء عدا المصنّف.

## الموقع التلقائي

من قسم «الموقع» في الشريط الجانبي:

- **📍 حدد موقعي تلقائيًا:** يطلب المتصفح إذن الموقع مرة واحدة عند فتح التطبيق (ويمكن الضغط على الزر لاحقًا لإعادة التحديد)، فيضبط خطّي العرض والطول ويجلب الارتفاع تلقائيًا. يعمل فقط على صفحات `https://` (مثل Streamlit Cloud) أو `localhost`، ولا يعمل عبر عنوان شبكة محلية مثل `http://192.168.x.x`.
- **🔎 البحث بالاسم:** اكتب اسم المدينة أو القرية، اختر النتيجة، ثم «استخدم هذا الموقع» (يأتي الارتفاع معها).
- أو اكتب الإحداثيات بيدك. تُظهر الخريطة الصغيرة النقطة للتأكد منها. يبقى تعديلك اليدوي عند التفاعل مع باقي الصفحة، ولا يتغيّر إلا إذا ضغطت زر التحديد مرة أخرى أو اخترت مكانًا.
- إن رفض المتصفح الإذن أو تعذّر التحديد يبقى الموقع السابق (الافتراضي: بنها) وتظهر رسالة.
- الخصوصية: الإحداثيات تبقى في جلسة التطبيق، وتُرسَل مقرّبة (خانتان عشريتان ≈ 1 كم) إلى NASA POWER وOpen-Meteo فقط.
- المصادر: أسماء الأماكن GeoNames، والارتفاع Copernicus DEM (90 م)، عبر Open-Meteo (مجاني للاستخدام غير التجاري مع ذكر المصدر).

## الطقس التلقائي من الإنترنت

اختر **«تلقائي من الإنترنت (NASA POWER)»** من الشريط الجانبي (وهو الخيار الافتراضي)؛ ينزَّل الطقس اليومي للموقع المحدد تلقائيًا بلا رفع ملفات ولا مفاتيح API:

- يُنزَّل من تاريخ الزراعة (أو آخر 4 سنوات على الأقل، أيهما أقدم) حتى آخر يوم منشور، ويُخزَّن مؤقتًا 6 ساعات لكل موقع وفترة.
- تنشر NASA الأرصاد بتأخير 2–3 أيام والإشعاع الشمسي بتأخير 5–7 أيام، لذلك يتوقف التنزيل عند «اليوم − 8 أيام»، وأي أيام لم تُنشر بعد تُحذف ولا تُملأ.
- المحاكاة تحتاج موسمًا كاملًا (145 يومًا). إن لم ينتهِ الموسم بعد، يُكمله التطبيق **بمتوسط السنين الماضية لنفس الأيام** (خيار «أكمل الموسم» في الشريط الجانبي، مفعّل افتراضيًا) مع تحذير ظاهر وملاحظة في التقرير. هذه الأيام **تقدير وليست طقسًا فعليًا**، والمطر المتوقع يُهمل غالبًا (أقل من 2 مم)، وتُستبدل بالقيم الفعلية تلقائيًا كلما نزلت بيانات جديدة. تبويب نموذج ET₀ يستخدم الأيام الفعلية فقط. عند إيقاف الخيار تظهر رسالة بآخر تاريخ زراعة ممكن.
- البيانات شبكية (≈55 كم) وليست قياس محطة: قارنوها بمحطة قريبة قبل أي استنتاج علمي.
- عند انقطاع الإنترنت أو الخدمة تظهر رسالة واضحة؛ استخدموا حينها «تجريبية» أو ملف CSV.

## خطوات الفريق بالترتيب

1. **الطقس الحقيقي:** الأسهل اختيار «تلقائي من الإنترنت» في الواجهة. ولحفظ ملف CSV: `python scripts/fetch_nasa_power.py --lat 30.46 --lon 31.18 --start 20200101 --end 20241231 --out data/nasa_benha.csv` ثم اختر «NASA POWER CSV» في الواجهة. يُفضّل أيضًا طلب بيانات محطة أرصاد قريبة من المشرف للمقارنة.
2. **نماذج ET₀:** `python scripts/evaluate_et0_models.py --nasa data/nasa_benha.csv` ← جدول مقارنة ورسم في `outputs/`.
3. **مصنّف الأمراض** (يُفضّل Google Colab بـ GPU): نزّلوا PlantVillage من Kaggle وضعوا مجلدات الطماطم العشرة في `data/plantvillage_tomato/`، ثم `python scripts/train_disease.py --data data/plantvillage_tomato --epochs 8`. الناتج `models/tomato_resnet18.pt` وتقارير الأداء ومصفوفة الالتباس.
4. **الاختبار الحقلي:** صور حقلية (PlantDoc + صور الفريق) في `data/plantdoc_tomato/<اسم الفئة>/` ثم أضيفوا `--external-test data/plantdoc_tomato`. هذا هو الرقم الأهم للتقرير لأن صور PlantVillage معملية، وتكرار الصور المتشابهة فيها يرفع الدقة الداخلية صناعيًا.
5. **مؤشر خطر الأمراض** افتراضي: عايروه ببيانات حقلية إن توفرت، أو اذكروه في التقرير كمؤشر استرشادي.

## ما الذي تم التحقق منه؟

- ✅ 43 اختبارًا آليًا ناجحًا: حساب ET₀ يطابق المثال 18 في FAO-56 (3.88 مم/يوم) وRa يطابق المثال 8، وحفظ الكتلة في الموازنة المائية، وقارئات الملفات، وقاعدة البيانات، وتقدير الإصابة على ورقة اصطناعية، والتنزيل التلقائي (بناء الطلب، إعادة المحاولة، تحويل وحدات الإشعاع، حذف الأيام غير المنشورة) بردود NASA مُحاكاة، والبحث عن المكان وجلب الارتفاع، وإكمال الموسم بالمتوسط المناخي، وسلوك زر الـ GPS (يحتاج Node.js وإلا يُتخطّى).
- ✅ منطق `app.py` جُرّب بمحاكي لـ Streamlit (`python tests/smoke_app.py`): عربي/إنجليزي، رفع صورة، حفظ، مسارات الخطأ، الطقس التلقائي مع خادم NASA مُحاكى، والموقع (GPS/بحث/يدوي) وإكمال الموسم.
- ⚠️ **لم يُجرَّب:** واجهة Streamlit الحقيقية، وتدريب/استدلال PyTorch، والتنزيل **الحي** من NASA POWER وOpen-Meteo، وزر الـ GPS داخل متصفح حقيقي (لم يتوفر إنترنت ولا متصفح في بيئة الإنشاء). جرّبوها وأبلغوا عن أي خطأ.
- ⚠️ بيانات الطقس الافتراضية **اصطناعية** للعرض فقط. وعلى هذه البيانات كانت Hargreaves **المعايَرة** (RMSE ≈ 0.47) أفضل من Random Forest بمدخلات الحرارة فقط (≈ 0.53): لا تدّعوا تفوق ML قبل مقارنته بـ Hargreaves المعايَرة على بيانات حقيقية.

## افتراضات علمية تحتاج مراجعة المشرف

- Kc للطماطم (0.60 / 1.15 / 0.80) ومدد المراحل (30/40/45/30 يومًا) وعمق الجذور وp=0.40 وKy=1.05: قيم افتراضية من FAO-56 وFAO-33، راجعوها من المراجع الأصلية وعدّلوها حسب الصنف وموعد الزراعة.
- رطوبة التربة FC/WP قيم نموذجية؛ كفاءة الري: تنقيط 0.90، رش 0.75، سطحي 0.60.
- الموازنة المائية مبسّطة: بلا جريان سطحي أو صعود شعري أو ملوحة، والمطر الأقل من 2 مم يُهمل.
- الإنتاج النسبي من معادلة Doorenbos-Kassam تقدير موسمي، وليس نموذج محصول.
- التوصيات إرشادية ولا تتضمن جرعات مبيدات، ولا تُغني عن المرشد الزراعي.
